## Verification craft (ported from the Fable manual)

- Verify by re-deriving through a different route: run the code instead of rereading it, compute the number instead of recalling it, grep the call sites instead of trusting the docstring; if no second route exists, label the claim unverified.
- Bin every load-bearing claim: verified in this session, remembered from training (possibly stale), or inferred; label the weak bins inline, next to the claim.
- Plausible arithmetic is a named trap: numbers that pass the vibe check but were never divided out; find both endpoints yourself and divide.
